# 第七章：安全加固篇 —— 防范攻击，守护数据

> **摘要**：NAS 是你家庭数据的核心，但也是黑客眼中的肥肉。本章将带你识别真实威胁，并逐层构建一套**纵深防御体系**，让你的 NAS 既能对外提供服务，又不会成为勒索病毒的下一个受害者。
>
> **核心目标**：从账户安全、网络加固到不可变快照，打造多层次的主动防御，将入侵风险降到最低。

---

## 7.1 威胁认知：NAS 面临的安全风险

在动手加固之前，我们需要先了解敌人是谁、用什么武器。

### 🚨 真实案例：针对 NAS 的勒索病毒

| 病毒名称      | 目标设备  | 攻击方式                                   | 影响                       |
| :------------ | :-------- | :----------------------------------------- | :------------------------- |
| **DeadBolt**  | QNAP/群晖 | 利用系统 0day 漏洞远程入侵                 | 加密所有文件，勒索比特币   |
| **QLocker**   | QNAP      | 利用 HBS 备份应用漏洞，将文件打包成加密 7z | 单次攻击影响数万台设备     |
| **eCh0raix**  | QNAP/群晖 | 暴力破解弱密码 + 利用已知漏洞              | 持续迭代，多年活跃         |
| **Checkmate** | QNAP      | 攻击暴露在互联网的 SMB 服务                | 加密文件并留下勒索信       |

> ⚠️ **残酷事实**：QNAP 和群晖等知名品牌的用户数量庞大，黑客专门针对这些设备开发"定制化"攻击工具。**越知名的品牌，越容易成为目标。**

### 🎯 常见攻击向量

1. **暴力破解 (Brute Force)**
   * 攻击者使用自动化工具，对暴露在公网的登录页面进行海量密码尝试。
   * **高风险场景**：开启了端口转发 + 使用 `admin/admin123` 这类弱密码。

2. **凭证填充 (Credential Stuffing)**
   * 利用其他网站泄露的账号密码组合，尝试登录你的 NAS。
   * **高风险场景**：多个平台使用同一套密码。

3. **漏洞利用 (Exploit)**
   * 攻击者扫描互联网上的设备，寻找未打补丁的旧版本 NAS。
   * **高风险场景**：购买后从不更新系统。

4. **端口扫描 (Port Scanning)**
   * 攻击者使用 Shodan、Censys 等引擎，批量发现暴露 5000/5001 端口的 NAS 设备。
   * **高风险场景**：直接用端口转发将管理页面暴露在公网。

## 7.2 账户与访问控制

账户安全是最基础也是最重要的防线。大多数成功的入侵，都始于一个弱密码。

### 7.2.1 禁用或重命名默认 admin 账户 🔑

所有 NAS 系统的默认管理员账户名称（如 `admin`）都是公开的，攻击者只需要猜密码。

**操作步骤 (通用思路)**：

1. **创建新管理员**：先创建一个新用户，赋予管理员权限，使用一个**不常见的用户名**（例如：`mje_boss`）。
2. **登录新账户**：使用新创建的管理员账户登录。
3. **禁用 admin**：回到用户管理，将原来的 `admin` 账户**禁用**（而非删除，以免影响某些系统服务）。

> 💡 **飞牛 (fnOS) 用户注意**：
> fnOS 默认管理员是 `admin`。可以在 `控制面板` -> `用户` 中创建新用户并赋予管理员角色，然后禁用 `admin`。

### 7.2.2 强密码策略 🔐

**密码要求**：
* 长度 ≥ 12 位
* 包含大小写字母、数字、特殊字符
* **不要**使用生日、手机号、常见单词

**工具推荐**：
* **Bitwarden / 1Password**：生成并管理高强度随机密码。
* **自建 Vaultwarden**：如果你不信任云服务，可以在 NAS 上自建密码管理器。

```bash
# 示例：生成 16 位随机密码 (Linux/Mac)
openssl rand -base64 16
```

### 7.2.3 启用多因素认证 (MFA/2FA) 🛡️

即使密码泄露，攻击者没有第二层验证码也无法登录。

**主流 NAS 系统设置路径**：

| 系统    | 设置入口                                                 |
| :------ | :------------------------------------------------------- |
| 群晖    | `控制面板` -> `安全性` -> `账户` -> `两步验证`           |
| QNAP    | `控制面板` -> `安全` -> `两步验证`                       |
| fnOS    | `控制面板` -> `用户` -> 选择用户 -> `启用两步验证`       |
| Unraid  | 需要安装插件（如 `CA User Scripts` 配合 TOTP 验证脚本）  |

**推荐验证器 App**：
* **Google Authenticator** / **Microsoft Authenticator**
* **Authy** (支持云同步，换手机不丢)

### 7.2.4 最小权限原则 📋

不要让每个家庭成员都使用管理员账户！

**实践建议**：
* **管理员账户**：仅供你自己使用，用于系统配置修改。
* **普通用户账户**：为家人创建独立账户，仅开放对特定共享文件夹的访问权限。
* **应用专用账户**：为 Jellyfin、qBittorrent 等 Docker 应用创建低权限账户。

## 7.3 网络安全加固

账户安全只是第一道门，网络层面的加固决定了敌人能否接近这道门。

### 7.3.1 VPN 优于端口转发 🏆

> **黄金法则**：如果可以不把 NAS 暴露在公网，就不要暴露。

| 方式       | 安全性 | 便捷性 | 推荐场景                   |
| :--------- | :----- | :----- | :------------------------- |
| 端口转发   | ⭐     | ⭐⭐⭐⭐⭐ | ❌ 不推荐（攻击面太大）      |
| Tailscale  | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐  | ✅ 个人远程管理首选         |
| WireGuard  | ⭐⭐⭐⭐⭐ | ⭐⭐⭐   | ✅ 极客/追求极致性能         |
| CF Tunnel  | ⭐⭐⭐⭐  | ⭐⭐⭐⭐  | ✅ Web 服务对外（非流媒体） |

**Tailscale 快速部署**（参考第二章）：
1. NAS 上安装 Tailscale 客户端并登录。
2. 手机/电脑安装 Tailscale 并登录同一账号。
3. 通过 `100.x.x.x` 内网地址访问 NAS，**无需任何端口转发**。

### 7.3.2 禁用 UPnP 自动端口映射 🚫

UPnP 会让路由器自动打开端口，绕过你的安全意识。

**操作步骤**：
1. 进入路由器后台。
2. 找到 `UPnP` / `通用即插即用` 设置。
3. **关闭它**。

*检查当前是否有设备自动打开了端口：进入路由器 `端口映射` 或 `NAT` 设置页面查看。*

### 7.3.3 修改默认服务端口 🔢

攻击者会优先扫描知名端口（如 5000/5001），修改为非标准端口可有效降低曝光率。

**常见服务的默认端口**：

| 服务         | 默认端口     | 建议修改为       |
| :----------- | :----------- | :--------------- |
| 群晖 DSM     | 5000/5001    | 50000+（如 50080）|
| QNAP QTS     | 8080/443     | 自定义高位端口    |
| SSH          | 22           | 22022 或其他      |

> ⚠️ **注意**：修改端口后，记得同步更新防火墙/端口转发规则（如果使用了的话）。

### 7.3.4 启用 IP 自动封锁 🚷

当检测到短时间内多次登录失败时，自动封锁该 IP 地址。

**群晖设置**：
`控制面板` -> `安全性` -> `保护` -> `启用自动封锁`
* **登录尝试次数**：5 次
* **时间范围**：5 分钟内
* **封锁天数**：永久 或 30 天

**QNAP 设置**：
`控制面板` -> `安全` -> `IP 访问保护`

**fnOS 设置**：
`控制面板` -> `安全` -> `自动封锁`

### 7.3.5 网络分段与 VLAN 隔离 (进阶) 🏗️

将 NAS 放在单独的 VLAN 中，即使其他设备被入侵，攻击者也难以横向移动到 NAS。

**适用人群**：使用软路由 (OpenWrt/OPNsense) 或企业级交换机的用户。

**基本思路**：
1. 创建一个 `Storage VLAN`（如 VLAN 10）。
2. 将 NAS 的网口划入该 VLAN。
3. 配置防火墙规则，仅允许特定设备（如你的电脑）访问 NAS。

## 7.4 系统更新与补丁管理

**未打补丁的系统是攻击者的乐园。**DeadBolt 等勒索病毒正是利用了 QNAP 系统的 0day 漏洞实现大规模入侵。

### 7.4.1 开启自动更新通知 🔔

大多数 NAS 系统支持自动检查更新并发送通知：

| 系统    | 设置入口                                    |
| :------ | :------------------------------------------ |
| 群晖    | `控制面板` -> `更新和还原` -> `更新设置`    |
| QNAP    | `控制面板` -> `固件更新` -> `更新计划`      |
| fnOS    | `系统设置` -> `系统更新`                    |

> 💡 **建议**：不要开启"自动安装更新"，因为某些更新可能引入兼容性问题。**自动通知 + 手动确认安装**是最佳实践。

### 7.4.2 关注官方安全公告 📢

将以下页面加入书签，定期查看：

* **群晖**：[Synology Security Advisory](https://www.synology.com/security/advisory)
* **QNAP**：[QNAP Security Advisory](https://www.qnap.com/security-advisory)
* **社区资讯**：Reddit `/r/synology`、`/r/qnap`、NAS 技术交流群

### 7.4.3 Docker 容器镜像更新策略 🐳

你 NAS 上的 Docker 容器也有漏洞！很多人部署完就不管了，这是巨大的安全隐患。

**手动更新流程**：
```bash
# 1. 拉取最新镜像
docker pull your-image:latest

# 2. 停止并删除旧容器
docker stop container_name
docker rm container_name

# 3. 使用原参数重新创建容器
docker run ... (原来的参数)
```

**自动化方案**：
* **Watchtower**：自动检测并更新容器镜像。
  ```bash
  docker run -d \
    --name watchtower \
    -v /var/run/docker.sock:/var/run/docker.sock \
    containrrr/watchtower \
    --schedule "0 0 4 * * *"  # 每天凌晨 4 点检查更新
  ```

> ⚠️ **警告**：Watchtower 会自动更新所有容器，某些应用更新后可能需要额外配置。生产环境建议仅通知不自动更新：`--monitor-only`。

## 7.5 不可变快照：勒索病毒的克星

即使攻击者入侵了你的 NAS 并加密了所有文件，只要有**不可变快照**，你就能一键回到加密前的状态。

### 7.5.1 快照机制简介 📸

**什么是快照？**
快照是文件系统在某一时刻的"冻结副本"。它利用写时复制 (CoW) 技术，只记录变化的数据块，因此非常节省空间。

**支持快照的文件系统**：
* **Btrfs**：群晖、fnOS 默认推荐
* **ZFS**：TrueNAS、Unraid (ZFS 插件)

### 7.5.2 配置定时快照策略 ⏰

**群晖 (Btrfs) 设置**：

1. 打开 `快照 & 复制 (Snapshot Replication)`。
2. 选择要保护的共享文件夹。
3. 配置快照计划：
   * **频率**：每天 1 次
   * **保留策略**：保留最近 30 个快照
4. **关键设置**：启用 `使快照对用户可见` 方便恢复，或**禁止普通用户删除快照**（防止攻击者删除快照）。

**fnOS (Btrfs) 设置**：
`存储管理` -> 选择存储池 -> `快照` -> `新增快照任务`

**TrueNAS (ZFS) 设置**：
`Storage` -> `Pools` -> 选择数据集 -> `Snapshots` -> `Add`

### 7.5.3 快照回滚演练 🔄

**没有测试过的备份/快照都是假的。**定期进行恢复演练，确保关键时刻能用。

**演练步骤**：

1. **创建测试文件**：在共享文件夹中新建一个 `test_restore.txt`。
2. **等待一次快照**：或者手动触发快照。
3. **模拟"加密"**：删除或修改 `test_restore.txt`。
4. **执行回滚**：
   * 群晖：`快照 & 复制` -> 选择快照 -> `还原`（可选择还原整个文件夹或单个文件）
   * fnOS：`快照` -> 选择时间点 -> `回滚`
5. **验证**：检查 `test_restore.txt` 是否恢复。

> ⚠️ **生产环境注意**：回滚会**覆盖**当前数据到快照时间点，请确保理解影响范围！

## 7.6 安全监控与告警

再好的防护也需要"眼睛"来监视。及时发现异常，才能快速响应。

### 7.6.1 启用登录日志审计 📋

记录所有登录尝试，包括成功和失败的。

**群晖**：`控制面板` -> `日志中心` -> `日志` -> 筛选 `连接`
**QNAP**：`控制面板` -> `系统日志` -> `连接日志`
**fnOS**：`日志中心` -> `系统日志`

**关注的异常模式**：
* 大量来自陌生 IP 的登录失败记录（暴力破解）
* 非正常时间段（如凌晨 3 点）的成功登录
* 来自海外 IP 的登录（如果你没有出国的话）

### 7.6.2 配置异常登录邮件告警 📧

**群晖设置**：
1. `控制面板` -> `通知设置` -> `电子邮件` -> 配置 SMTP 服务器（如 QQ 邮箱）。
2. `控制面板` -> `安全性` -> `账户` -> 勾选 `用户登入时发送邮件通知`。

**QNAP 设置**：
`控制面板` -> `通知中心` -> `服务账户和设备配对` -> 添加电子邮件账户。

**推送替代方案**：
* **Bark (iOS)**：自建推送服务，秒级送达。
* **PushPlus / Server酱**：微信推送通知。

### 7.6.3 系统资源异常监控 📊

勒索病毒加密文件时会产生**异常的 CPU 和磁盘活动**。

**监控建议**：
* 部署 **Netdata** / **Prometheus + Grafana**，监控 CPU、磁盘 I/O、网络流量。
* 设置阈值告警：
  * CPU 持续 100% 超过 5 分钟 -> 告警
  * 磁盘写入异常飙升 -> 告警

## 7.7 安全检查清单 (Checklist)

打印这份清单，逐项核对你的 NAS 安全配置：

### ✅ 账户安全
- [ ] 已禁用或重命名默认 `admin` 账户
- [ ] 所有账户使用 ≥12 位强密码
- [ ] 管理员账户已启用两步验证 (MFA)
- [ ] 普通用户仅拥有必要的最小权限

### ✅ 网络安全
- [ ] 未使用端口转发暴露管理页面
- [ ] 已禁用路由器 UPnP 功能
- [ ] 已修改默认服务端口 (如 5000 -> 50080)
- [ ] 已启用 IP 自动封锁 (5 次失败/5 分钟内)
- [ ] 远程访问使用 VPN (Tailscale/WireGuard) 或 CF Tunnel

### ✅ 系统更新
- [ ] 已开启系统更新通知
- [ ] 定期检查并安装安全补丁
- [ ] Docker 容器定期更新或配置 Watchtower 监控

### ✅ 数据保护
- [ ] 已配置定时快照 (每天至少 1 次)
- [ ] 快照保留策略 ≥ 7 天
- [ ] 已进行过快照恢复演练
- [ ] 已配置异地加密备份 (参考第六章 Rclone)

### ✅ 监控告警
- [ ] 已启用登录日志记录
- [ ] 已配置登录告警通知 (邮件/微信/Bark)
- [ ] (可选) 已部署资源监控工具 (Netdata/Grafana)

## ✅ 本章小结

恭喜你！完成了这些配置后，你的 NAS 已经从"裸奔"状态进化成了一座"数字堡垒"：

| 防御层次     | 你获得的能力                               |
| :----------- | :----------------------------------------- |
| **账户层**   | 强密码 + MFA，暴力破解无效                 |
| **网络层**   | VPN 隧道 + IP 封锁，攻击者找不到入口       |
| **系统层**   | 及时更新，漏洞利用窗口最小化               |
| **数据层**   | 不可变快照，勒索加密可一键回滚             |
| **监控层**   | 异常告警，入侵行为第一时间发现             |

> 💡 **安全是一种持续的状态，而非一次性的配置。**
>
> 建议每季度回顾一次本章清单，检查是否有新的安全更新或配置调整需要处理。
