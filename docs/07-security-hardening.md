# 第七章：安全加固篇 —— 纵深防御与主动安全

> **摘要**：安全不是一个开关，而是一个过程。本章将带你**透视黑客的攻击视角**，从 WebUI 漏洞原理到网络扫描机制，知其然更知其所以然。我们将构建一套基于**“零信任”**理念的纵深防御体系，让你的 NAS 坚如磐石。
>
> **核心目标**：理解攻击链条，通过**隐身、隔离、加密**三道防线，化解勒索病毒与定向攻击的威胁。

---

## 7.1 透视黑客视角：你的 NAS 是如何被攻破的？

在防御之前，我们需要先像黑客一样思考。攻击往往遵循严密的**杀伤链 (Kill Chain)**：

### 🚨 阶段一：侦察与扫描 (Reconnaissance)

攻击者并不会盯着你一个人攻击，他们使用自动化工具进行全网撒网。

* **Shodan / Censys / Fofa**：这些是“黑暗搜索引擎”。黑客只需搜索 `port:5000 country:CN`，就能瞬间获得成千上万台暴露在公网的群晖 NAS 列表。
* **指纹识别**：通过 HTTP 响应头（如 `Server: nginx`）、网页标题（如 `Synology DSM`），攻击者能精准判断你的系统版本。

### 🚨 阶段二：武器化与入侵 (Weaponization & Exploit)

一旦锁定了目标，攻击者会尝试利用已知漏洞：

* **WebUI 漏洞 (最致命)**：NAS 的管理页面（WebUI）是极其复杂的 Web 应用。
  * **历史教训**：**DeadBolt** 和 **QLocker** 勒索病毒利用的是 **未经身份验证的远程代码执行 (RCE)** 漏洞，直接在底层植入木马。
  * **最新威胁（2026 飞牛 fnOS 事件）**：攻击者利用的是 **未经身份验证的路径穿越 (Path Traversal)** 漏洞。
    * **原理**：黑客发送一个精心构造的 URL 请求（例如包含 `../../` 字符的请求），试图“跳出” Web 服务的预设路径限制，直接访问系统根目录文件。

    * **危害**：在飞牛事件中，攻击者无需登录账号，即可绕过登录界面直接读取系统敏感配置文件（如 `/etc/shadow`）或用户的存储数据。
    * **厂商响应**：飞牛官方发布紧急补丁 (v1.1.15) 阻断攻击，并随后发布 **v1.1.18** 彻底修复了底层逻辑。

> **⚠️ 核心警示**：面对这种“绕过登录流程”的漏洞，**再强的密码和 MFA 都是无效的**。只要你的管理端口（如飞牛默认的 `8000/8001`）直接暴露在公网，就始终面临 0-day 漏洞的威胁。

* **暴力破解 (Brute Force)**：对于暂时没有 0-day 漏洞的系统，攻击者会采取“笨办法”。
  * **手段**：调用仅仅几百 MB 的“弱口令字典”，利用自动化脚本全天候轰炸你的 SSH (22) 或 Web 登录接口。
  * **现状**：如果你的管理界面暴露在公网，查看系统日志你会发现，每分钟都有来自全球各地的 IP 在尝试用 `admin`、`root`、`123456` 敲你的门。

### 🚨 阶段三：横向移动与加密 (Lateral Movement & Action)

攻破入口后，勒索病毒会：

1. **提权**：获取 Root 权限。
2. **横向移动**：扫描局域网内的其他电脑（Windows/Mac），加密所有挂载的 SMB 共享盘。
3. **加密勒索**：使用高强度算法（AES+RSA）加密文件，并在每个目录留下 `.txt` 勒索信。

## 7.2 第一道防线：网络隐身 (Network Stealth)

既然 WebUI 漏洞可能绕过登录验证，那么**最好的防御就是让黑客根本“看不见”你的登录页面**。

### 7.2.1 IPv6 防火墙：默认拒绝 (Default Deny) 🚧

随着 IPv6 的普及，通过光猫桥接获取公网 IPv6 地址已成为主流。但这带来了一个巨大风险：**IPv6 地址是全球可达的，绕过了传统的 NAT 保护。**

* **风险**：如果你的路由器/光猫防火墙配置不当，你的 NAS 每个端口都直接暴露在互联网上。
* **正确实践**：
  * 在路由器防火墙规则中，将 IPv6 入站 (Input/Forward) 默认为 **DROP/REJECT**。
  * **绝对不要**放行 5000/5001/8080/443 等管理端口。
  * 仅按需放行 P2P 下载 (如 TCP/UDP 16881) 等特定业务端口。

### 7.2.2 实战：IPv6 + DDNS 的安全生存指南 (必读) 🛡️

很多用户为了追求速度使用 **IPv6 + DDNS** 直连 NAS，这相当于把 NAS 挂在公网上。**如果必须这样做，请恪守以下三大铁律**：

**1. 业务分离原则 (Separation of Concerns)**

* **可以露的**：Plex / Emby / Jellyfin 等媒体服务端口。
  * *理由*：这些服务只读属性强，且通常有独立的账号鉴权，即使被攻破也就是泄露片源，不会导致系统级沦陷。
* **绝对不能露的**：
  * **管理后台 (5000/5001/8080)**：攻击者拿到这个就能格式化你的硬盘。
  * **SSH (22/22022)**：攻击者拿到这个就能控制底层系统。
  * **数据库 (3306/5432)**：纯粹的数据裸奔。

**2. 安全入口：Nginx Proxy Manager (NPM)**
不要直接把应用端口暴露给公网，而是通过反向代理统一管理。

* **部署 NPM**：只在路由器防火墙放行 NPM 的 `80/443` 端口。
* **SSL 证书**：自动为所有服务申请 Let's Encrypt 证书，加密传输流量。
* **Access Lists**：NPM 支持简单的访问控制列表，可以限制仅允许特定 IP 段访问特定服务。

**3. 降维打击：VPN over IPv6**
利用 IPv6 的大带宽优势，搭建 **WireGuard** 或 **Tailscale (Derp)** 隧道。

* **日常管理**：先连 VPN，再用局域网 IP 管理 NAS。
* **观影刷剧**：才走 DDNS 直连域名。

### 7.2.3 端口隐匿与修改 🔢

* **修改默认端口**：将 SSH (22) 改为高位端口（如 22022），将管理面板端口改为不常见端口。这虽然不能防御定向攻击，但能避开 99% 的自动化脚本扫描。
* **禁用 UPnP**：通用即插即用 (UPnP) 是内网穿透的“后门”，很多设备会悄无声息地通过它打开公网端口。**请在路由器中彻底关闭 UPnP。**

### 7.2.4 地域封锁 (GeoIP Blocking) 🌏

绝大多数针对 CN 用户的自动化扫描来自海外。

* **策略**：在 NAS 或路由器的防火墙中，配置 **“仅允许中国大陆 IP 访问”**。
* **效果**：这一条简单的规则，就能让你的系统日志清净 90% 以上。

## 7.3 第二道防线：安全隧道 (Secure Tunneling)

如果必须远程访问管理后台，请披上一层加密的“隐形衣”。

### 7.3.1 放弃端口转发，拥抱 VPN 🏆

**端口转发 (Port Forwarding)** 是将内网端口直接映射到公网，等于把大门敞开。

**推荐方案**：

| 方案           | 穿透机制             | 优点                  | 缺点                                   |
| :------------- | :------------------- | :-------------------- | :------------------------------------- |
| **VPN 直连**   | WireGuard / IPv6     | 速度极快，私密性最高  | 需手动配置客户端                       |
| **SD-WAN**     | Tailscale / ZeroTier | 零配置，打洞穿透      | 依赖官方服务器中转，可能受网络波动影响 |
| **Zero Trust** | Cloudflare Tunnel    | 带身份验证的 Web 代理 | 国内连接速度受限                       |

**最佳实践**：
使用 **Tailscale** 或 **ZeroTier** 构建虚拟局域网。当你需要管理 NAS 时，先连接 VPN，然后像在家里一样通过内网 IP（如 `192.168.1.10`）访问。**这样，公网上根本没有开放任何端口。**

## 7.4 第三道防线：身份与供应链 (Identity & Supply Chain)

### 7.4.1 账户零信任 🔐

* **禁用默认 Admin**：这是攻击者字典里的 No.1。
* **多因素认证 (MFA)**：为所有管理员账户开启 MFA。推荐使用 **Microsoft Authenticator** 或 **腾讯身份验证器** 等支持云同步的工具，防止手机丢失导致无法登录。
* **密码管理**：使用 **Bitwarden** (可自建 Docker 版) 生成并存储 16 位以上随机密码。

### 7.4.2 供应链安全：Docker 镜像源 🐳

**痛点**：由于网络原因，国内用户经常无法连接 Docker Hub，导致容器长期无法更新，积累大量漏洞。

**解决方案**：配置国内 **Registry Mirrors (镜像加速源)**。这是确保你能够及时获取安全补丁的关键。

**配置示例 (`/etc/docker/daemon.json`)**：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://huecker.io",
    "https://dockerhub.timeweb.cloud"
  ]
}
```

*注：镜像源地址变动频繁，建议关注 [Awesome-NAS-Guide 相关 Issue](https://github.com/jyma/Awesome-NAS-Guide/issues) 获取最新可用源。*

## 7.5 最后一道防线：数据兜底 (Data Resilience)

如果前三道防线全部失守，黑客已经坐在你的系统里了，你还有最后一张底牌。

### 7.5.1 不可变快照 (Immutable Snapshots) 📸

勒索病毒可以加密文件，但无法修改“过去”。
利用 **Btrfs** 或 **ZFS** 的写时复制特性 (CoW)，开启定时快照（如每小时一次）。

* **恢复**：一旦中招，只需在快照列表中选择中毒前的时间点，点击“还原”，瞬间穿越回去。

### 7.5.2 异地加密备份 (Off-site Backup) ☁️

遵循 3-2-1 原则，利用 **Rclone Crypt** 将核心数据加密打包，上传至 **阿里云盘、115 或对象存储 (S3)**。

* 即使 NAS 被物理摧毁，数据依然在云端安然无恙且由于加密保护，隐私不会泄露。

---

## 7.6 全方位感知：现代化告警 📢

不要指望你会每天登录后台看日志。告警必须“推”到你脸上。

* **IM 推送**：放弃邮件，使用 **Webhook** 将告警接入 **微信 (PushPlus/Server酱)**、**飞书** 或 **钉钉** 群机器人。
* **监控指标**：
  * **异常登录**：任何非白名单 IP 的登录成功事件。
  * **资源异常**：CPU 持续 100% 或磁盘 I/O 异常飙升（勒索病毒加密时的特征）。

* [ ] 路由器 IPv6 防火墙默认策略为 DROP
* [ ] 仅放行必要的 P2P 业务端口
* [ ] 已关闭路由器 UPnP
* [ ] 配置了 GeoIP 规则（仅限 CN IP）

### ✅ 访问层

* [ ] 远程管理使用 VPN/SD-WAN，未直接暴露 WebUI
* [ ] 已修改 SSH 默认端口 (22)

### ✅ 身份层

* [ ] 默认 Admin 已禁用
* [ ] 管理员账户已开启 MFA
* [ ] 强密码策略生效中

### ✅ 数据层

* [ ] 定时快照策略已生效 (每日/每小时)
* [ ] Docker 镜像源配置正确，能正常拉取更新
* [ ] 异地加密备份任务正常运行
